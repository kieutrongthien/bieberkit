# BieberKit 0.4.1 beta

Package version: **0.4.1** for all 26 packages and plugins. npm dist-tag: **beta**. Release git tag: **v0.4.1-beta**.

**Publish [0.4.0](0.4.0-beta.md) first.** Every `0.x` version is published under `beta`, so a `0.4.0` that is published after this one moves `beta` back to it.

## Changes

- Every file of a module and of a plugin is in the folder of its kind (`entities/`, `services/`, `routes/`, `jobs/`, `events/`, and in `admin/` the folders `pages/`, `tabs/`, `fields/`, `components/`, `lib/`, `messages/`), see [file layout](../modules/file-layout.md) (MOD-19).
- `bieberkit make:plugin` writes this layout, and the `AGENTS.md` of a new project says it.
- `bieberkit check layout` is new. It warns about a file that is out of place (`BK_LAYOUT_MISPLACED`) and does not fail the check.
- The base plugins and the shell of the admin were reorganized. Their public exports, routes and their schemas, jobs, subscriptions, settings and admin slots are the same.

## Upgrade

Nothing breaks and no table changes. A project with its own plugins or modules may now see warnings from `bieberkit check`: move the files, or leave them.

## Local verification

Run on 2026-11-28 with Node.js 26.13.1 and pnpm 12.21.0.

On the tree of this release, with the versions at `0.4.1`: `pnpm build`, `pnpm typecheck`, `pnpm lint`, `pnpm check`, `pnpm format:check`, `pnpm check:api` (61 reports), `pnpm check:packages` (26 tarballs) and `pnpm test:artifacts` (5 passed) passed.

On the tree before the version bump (`4b6de6f`) or shortly before it. **These were not run again at `0.4.1`:**

- The unit tests of what changed: the six plugins, the CLI, the scaffolder and the admin shell.
- `e2e/slots.spec.ts`, `e2e/account.spec.ts` and `e2e/screens.spec.ts`: 46 passed.
- `pnpm test:acceptance`: passed (19 steps).

Not run: the whole unit suite, the other browser test files, the three-dialect run, Node.js 24.12, a real `docker build` and CI.

## Publication handoff

1. Push `main` and let CI pass.
2. Tag `v0.4.0-beta` on the commit `34e6a78` ("prepare 0.4.0 beta"), push the tag, approve the `release` environment and wait until it has published.
3. Then tag `v0.4.1-beta` on the release commit of this version and do the same ([the release runbook](../releasing.md)).
4. Check that the npm `beta` tag points at `0.4.1`.
