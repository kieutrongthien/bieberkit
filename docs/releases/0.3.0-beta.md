# BieberKit 0.3.0 beta

Package version: **0.3.0** for all 26 packages and plugins. npm dist-tag: **beta**. Release git tag: **v0.3.0-beta**. The version has no prerelease suffix (PLG-08, ADR 0014).

## Highlights

- The base plugins (users, roles, settings, notifications, media, audit log) are complete on the API side, with declared settings, security policies, managed identities, delegated administration and operations for an enterprise.
- Plugin system: entity extensions, `bieberkit make:plugin`, the plugin dependency graph, a safer `bieberkit remove`, checks for plugin boundaries and plugin tables, and a named deploy (`DEPLOY_ID`) for expand then contract.
- Admin: conditional, file, image and inline fields, search, filters and saved views, bulk actions, CSV export, state moves, related records and history, brand tokens, English, Vietnamese and Chinese, a small screen layout, resilience, client error reports, and plugin contributions.
- `pnpm create bieberkit` asks with arrow keys, and a new project starts with `pnpm dev`.

The package changelogs hold the full list.

## Breaking changes

| Area            | Change                                                                                                                                                                                                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users and roles | The users list answers `{ data, meta }` and takes `pageSize` in place of `limit`. Assign and revoke take `userIds` and answer `results`. The permissions route answers objects. Deleting a role with members needs `reassignTo`. A role can only be created, changed or given by someone who holds its permissions. |
| Settings        | The generated entity routes of `settings.Setting` are gone, and an undeclared key is `SETTINGS_UNKNOWN_KEY`.                                                                                                                                                                                                        |
| Notifications   | The entity routes keep only list, get and delete. Create with `POST /api/v1/notifications/send` and the permission `notifications.send`. With the sync queue, await `queue.settle()` before reading the effect of a job.                                                                                            |
| Media           | The plugin's own routes replace the generated ones. `PATCH` changes metadata only, `pathOf` takes the tenant, and a refused upload is `rejected`.                                                                                                                                                                   |
| Audit log       | The entries list takes `pageSize` in place of `limit` and answers `meta.nextCursor`. In a tenant it shows that tenant's entries only.                                                                                                                                                                               |
| Admin library   | `MESSAGES` is replaced by `loadMessages(locale)` and `ENGLISH`, and `translator` takes a dictionary.                                                                                                                                                                                                                |
| CLI kit         | The `Ask` function is replaced by the `Prompts` port.                                                                                                                                                                                                                                                               |

## Upgrade and deployment

After publication, install with `pnpm add @bieberkit/core@beta`, or scaffold with `pnpm create bieberkit@beta my-app`. Generated projects enforce a seven-day release age (SEC-11).

Run the deployment migrations before starting application roles. The changesets of this release name new data and auth migration steps (data 0.5.0, auth 0.6.0 and 0.7.0). Step versions are separate from the npm package version. `bk_settings` gains `scope` and `secret_value`, and its key is unique for each scope: a project picks this up with `bieberkit migrate:make`.

2. Check the items of [the release runbook](../releasing.md) that are still open before the first publish from GitHub.
3. Create the tag `v0.3.0-beta` on that `main` commit, push the tag and approve the `release` environment only after `verify` and `build` pass.
